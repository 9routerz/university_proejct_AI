# Deploy guide

```
Participant's browser
   │
   ▼
PHP UI (Hostinger)  ──►  FastAPI backend (Render)  ──►  Claude (9router on Railway)
  php-frontend/            main.py, agent.py              writes pandas code
                                  │
                                  ├──►  E2B sandbox (cloud)   runs the code on df
                                  └──►  Redis (Render)        sessions, history, timer
```

## 1. Backend on Render

1. Push this branch to GitHub.
2. On https://render.com: **New > Blueprint**, pick the repo. `render.yaml` creates:
   - `ds-competition-api` (the FastAPI web service)
   - `ds-competition-redis` (Key Value / Redis, `REDIS_URL` is filled in automatically)
3. Render asks for the secret values:

   | Variable | Value |
   |---|---|
   | `CLAUDE_BASE_URL` | Your 9router URL, `https://ninerouterapi.onrender.com` (no `/v1` at the end) |
   | `CLAUDE_API_KEY` | Your 9router API key |
   | `CLAUDE_MODEL` | `cc/claude-opus-5` (any model name from your 9router dashboard) |
   | `E2B_API_KEY` | From https://e2b.dev > Dashboard > API Keys |

   `BACKEND_SECRET` and `ADMIN_KEY` are generated by Render automatically. Copy `BACKEND_SECRET`
   from the service's **Environment** tab; the PHP UI needs the same value.
4. When deployed, open `https://<your-service>.onrender.com/health`. You should see `"redis": "connected"`.

The dataset the participants get is `data/messy_dataset.csv`. To use the final competition dataset, replace that file and push.
Never commit the clean reference / answer-key CSV to a public repo.

## 2. PHP UI on Hostinger

1. Make the settings file from `php-frontend/.env.example`:
   ```
   BACKEND_URL=https://<your-service>.onrender.com
   BACKEND_SECRET=<same value as on Render>
   ACCESS_CODE=<optional code you tell participants on the day>
   ```
   Upload it to the folder **above** `public_html` as `ds-competition.env` (safest: the web can't reach it).
   If you can't, upload it as `.env` next to `index.php`; `.htaccess` blocks it from the web.
2. In Hostinger hPanel > **File Manager**, open `public_html` (or a subfolder) and upload
   `index.php`, `api.php`, `app.js`, `bootstrap.php` and `.htaccess` from `php-frontend/`.
3. Turn on SSL for the domain in hPanel. `.htaccess` then forces HTTPS.
4. Open your domain. Enter a name, click **Begin session** and chat.

## 3. Run everything on your PC (for testing)

```bash
pip install -r requirements.txt
copy .env.example .env                   # fill in your keys, REDIS_URL=memory:// needs no Redis
copy php-frontend\.env.example php-frontend\.env   # BACKEND_URL=http://127.0.0.1:8000 + same BACKEND_SECRET
uvicorn main:app --port 8000
php -S 127.0.0.1:8080 -t php-frontend
```
Open http://127.0.0.1:8080

## Security

| Layer | What protects it |
|---|---|
| Backend API (Render) | Every endpoint except `/health` needs the `X-Backend-Secret` header. Only the PHP server knows it, so students can't call the API directly (e.g. to score again or read other sessions). `/reset` needs `X-Admin-Key`. `/docs` is off. CORS is closed. Errors don't leak internal details. |
| PHP UI (Hostinger) | Session ID, backend URL and secret never reach the browser. CSRF token on every call, `HttpOnly` + `SameSite=Strict` cookies, rate limits, optional access code with lockout after 5 wrong tries. |
| Browser | Strict Content-Security-Policy (no inline or outside scripts), no framing, all output escaped. |
| `.htaccess` | Forces HTTPS, blocks `.env` / dot-files / `bootstrap.php`, no directory listing. |
| Sandbox | AI code runs only inside E2B, never on Render. Dangerous code patterns are blocked first. |
| Secrets | Only in `.env` files (git-ignored) and Render's environment settings. |

## Things to know

- **Render free plan sleeps** after ~15 minutes without traffic. The first request then takes ~1 minute.
  Open `/health` a few minutes before the competition starts, or use a paid plan on the day.
- **E2B free plan** limits how many sandboxes run at the same time and keeps each one up to 1 hour.
  Check https://e2b.dev/pricing against the number of participants.
- Each participant can only be scored once; scoring ends their session.
